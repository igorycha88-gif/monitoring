# ЧТЗ: Дашборды Вебмастера — динамика по дням и топ запросов

- Дата: 2026-08-19
- Источник: запрос пользователя (4 среза данных Вебмастера)
- Архитектура: `требования/ADR-008_Дашборды_Вебмастера_динамика_и_топы.md`
- Маршрут: Аналитик → Архитектор → Аналитик → **Разработчик → Тестировщик → DevOps**

## 1. Цель

Дать пользователю 4 представления данных Яндекс.Вебмастера в Grafana:

1. Показы сайта в поиске **по дням** (timeseries);
2. Клики сайта в поиске **по дням** (timeseries);
3. **Топ-5 запросов по позиции** — срезы неделя / месяц / год;
4. **Топ-5 запросов по кликам** — срезы неделя / месяц / год.

Организация (решение пользователя): **2 дашборда**; срезы месяц/год —
приближённо из накопленной истории Prometheus (API отдаёт только неделю).

## 2. Что делаем

### TASK-BCK-1: Дневная история в коллекторе (per-query)

> Поправка (2026-08-19, по итогам проверки живого API): site-level
> `/search-queries/history` НЕ существует (404 RESOURCE_NOT_FOUND).
> Реализация — per-query история `/search-queries/{query_id}/history`
> для каждого запроса топа; сайт-уровень = `sum()` на дашборде.

- `collectors/webmaster.py`: `QueryStats` + `query_id` (обязателен в
  popular-ответе); после `/popular` — последовательные per-query history
  запросы (`query_indicator=TOTAL_SHOWS,TOTAL_CLICKS`, окно
  `webmaster_history_days`, даты YYYY-MM-DD).
- Разбор ответа `{indicators: {TOTAL_SHOWS: [{date, value}], TOTAL_CLICKS:
  [...]}}`; **пишется только новейшая ЗАВЕРШЁННАЯ точка** — точки с датой
  «сегодня» (таймзона Яндекса +03:00, незавершённый день с нулями)
  исключаются; пустой/отсутствующий индикатор — не пишется (не 0).
- 404 на конкретный запрос (QUERY_ID_NOT_FOUND) — пропуск с warning-логом
  (host-404 уже отсечён /popular, который выполняется первым).
- Метрики (gauge, `{site, query}`, без лейбла даты):
  - `monitoring_search_daily_clicks`
  - `monitoring_search_daily_shows`
- Обработка статусов/ретраев — переиспользуется (429/401/403/5xx, ADR-004).
- `app/config.py`: `webmaster_history_days: int = 7` (clamp 1..31);
  `app/main.py`: передача в коллектор; `.env.example`: `WEBMASTER_HISTORY_DAYS=7`.
- Логирование: `webmaster_history_written` (site, query, clicks, shows),
  `webmaster_history_query_skipped`, `webmaster_history_done`.

### TASK-INF-1: Retention Prometheus 400d

- Флаг `--storage.tsdb.retention.time=400d` задаёт
  `prometheus/prometheus-entrypoint.sh` (проброс `"$@"`); в compose
  `command` флаг НЕ дублируется (повтор флага = crash Prometheus).
- Годовой срез `[365d]` требует хранения ≥ 1 года (сейчас дефолт 15d).

### TASK-FRT-1: Дашборд «Поиск: динамика показов и кликов»

- `grafana/dashboards/webmaster-dynamics.json`, uid `webmaster-dynamics`.
- Переменная `site` = `label_values(monitoring_search_daily_shows, site)`.
- Панели: «Показы по дням», «Клики по дням» (timeseries, range-запросы
  `sum(monitoring_search_daily_*{site="$site"})` — сайт = сумма по
  отслеживаемым запросам, приближение помечено в описании дашборда).

### TASK-FRT-2: Дашборд «Поиск: топ запросов»

- `grafana/dashboards/webmaster-top-queries.json`, uid `webmaster-top-queries`.
- Переменные: `site` (аналогично) + `period` (custom: Неделя=7d,
  Месяц=30d, Год=365d).
- Панели-таблицы (instant):
  - «Топ-5 запросов по позиции (лучшие)»:
    `bottomk(5, avg_over_time(monitoring_search_position{site="$site"}[$period]))`;
  - «Топ-5 запросов по кликам»:
    `topk(5, avg_over_time(monitoring_search_clicks_total{site="$site"}[$period]))`;
  - «Топ-5 запросов по показам»:
    `topk(5, avg_over_time(monitoring_search_shows_total{site="$site"}[$period]))`.
- В описании дашборда: «Месяц/Год — приближение из накопленных недельных
  данных (неделя — точно из API)».
- Колонки таблиц: `query` → «Запрос», `Value` — смыслные названия.

## 3. Критерии приёмки

1. После деплоя `/metrics` содержит `monitoring_search_daily_clicks` /
   `monitoring_search_daily_shows` для сайтов с `webmaster_host_id`.
2. Grafana: дашборд «Поиск: динамика показов и кликов» строит графики по
   дням (после суточного накопления точек).
3. Дашборд «Поиск: топ запросов»: переключение `period` (7d/30d/365d) меняет
   срезы; таблицы топ-5 по позиции (bottomk)/кликам/показам отображаются.
4. `pytest && ruff check . && ruff format --check . && mypy .` — зелёные.
5. Retention Prometheus = 400d (флаг в compose, проверка тестом).
6. Существующие коллекторы/дашборды не сломаны (регрессия).
7. Секреты не в коде; токен не логируется.

## 4. Ограничения

- Метрика дня пишется меткой времени сбора (лаг Яндекса ~1 сутки) — сдвиг
  равномерный, допустимо (ADR-008 D1).
- Годовой срез пуст первые месяцы накопления; требует retention 400d и
  свободного диска на VPS (DevOps проверяет при деплое, рекомендация ≥5 ГБ).

## 5. Риски

- Изменение формата API — изолировано моками respx.
- Диск VPS — контроль на деплое; при нехватке retention снизить (D4 ADR-008).
