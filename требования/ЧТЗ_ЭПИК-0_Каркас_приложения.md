# ЧТЗ ЭПИК-0: Каркас приложения (Foundation)

**Дата:** 2026-08-14
**Маршрут:** Аналитик → Архитектор (ADR-001 ✅) → Аналитик → Разработчик → Тестировщик → DevOps
**Связанные документы:** `требования/BACKLOG.md` (ЭПИК-0), `требования/ADR-001_Каркас_и_модель_метрик.md`, `ARCHITECTURE.md`

## 1. Цель

Работающий скелет: FastAPI-сервис с `/health`, `/metrics`, `/api/v1/sites`,
валидацией `config/sites.yml`, базовым классом коллекторов и полной локальной
инфраструктурой Docker (app + Prometheus + Grafana), на которой собираются
ЭПИК-1..8.

## 2. Объём работ (in scope)

| ID | Задача | Детали |
|----|--------|--------|
| TASK-001 | FastAPI-каркас | `app/main.py` (lifespan: structlog + APScheduler), `app/config.py` (pydantic-settings), `app/logging.py` (structlog JSON), middleware логов request/response |
| TASK-002 | Конфиг сайтов | `app/sites.py`: pydantic-модели, загрузка YAML, валидация (пустой домен, схема в домене, дубли, unknown-поля), ошибки `SiteConfigError` |
| TASK-003 | BaseCollector | `collectors/base.py`: `collect_site()` abstract, `run_once()` (пер-site try/except, метрики+логи), `retry()` (backoff, настраиваемый `retry_on`), `register()` (APScheduler) |
| TASK-004 | API | `GET /health` → `{"status":"ok"}`; `GET /api/v1/sites` → `{count, sites[]}` |
| TASK-005 | Инфраструктура | Dockerfile (python:3.12-slim, healthcheck), docker-compose (3 сервиса, порты 127.0.0.1:8088/9091/3300, сеть monitoring-net), prometheus.yml (scrape 15s), grafana provisioning |
| TASK-006 | Качество | pyproject: pytest+pytest-asyncio+respx+pytest-cov, ruff, mypy strict (pydantic plugin); `config/sites.yml` с 2 демо-сайтами; `.env.example` |

## 3. Вне объёма (out of scope)

Конкретные коллекторы (ЭПИК-1/2/5/6), дашборды Grafana (ЭПИК-3), прод-деплой
(ЭПИК-4), алерты (ЭПИК-7), реальное использование токенов Яндекса.

## 4. Требования

1. **R1 Секреты**: только `.env` (chmod 600) через pydantic-settings; в коде/коммитах — никогда; `.env.example` — шаблон.
2. **R2 Логирование** (Правило 8): middleware логирует `http_request` (method, path, status, duration_ms); BaseCollector — начало/конец цикла, результат по сайту, ошибки с `error`+`operation`; все except-блоки логируются.
3. **R3 Метрики** (Правило 8): `monitoring_collector_success{source,site}`, `monitoring_collector_errors_total{source,site}`, `monitoring_collector_duration_seconds{source,site}` пишет базовый класс.
4. **R4 Надёжность**: ошибка одного сайта не прерывает цикл сбора; `/api/v1/sites` при битом конфиге возвращает 500 с понятным detail.
5. **R5 Изоляция**: порты публикуются только на 127.0.0.1; compose project `monitoring`; имена контейнеров `monitoring-*`.
6. **R6 Типизация**: mypy strict, все публичные функции аннотированы.

## 5. Критерии приёмки

1. `pytest && ruff check . && ruff format --check . && mypy .` — зелёные; покрытие новых файлов ≥ 60% (enforced через `--cov-fail-under=60`)
2. Автотесты покрывают: health, sites-API (валидный/битый конфиг), загрузчик sites.yml (7+ кейсов), BaseCollector (успех/ошибка/метрики/ретраи/расписание), логирование (capture_logs)
3. `docker compose -p monitoring up` → все 3 сервиса healthy; `/health` 200, `/metrics` 200, Prometheus `/-/healthy` OK, Grafana `/api/health` OK
4. В `/metrics` присутствуют метрики формата `monitoring_*` (после первого цикла любого коллектора; в ЭПИК-0 — подтверждено юнит-тестами)
5. Grafana: anonymous отключён, datasource Prometheus загружен через provisioning
