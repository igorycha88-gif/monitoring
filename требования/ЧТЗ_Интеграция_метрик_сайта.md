# ЧТЗ: Интеграция мониторинга с метриками сайта da-dryclean.ru (site-metrics)

> Версия: 1.0 · Дата: 2026-08-18 · Эпик: ЭПИК-9 · ADR: ADR-007
> Маршрут: Разработчик → Тестировщик → DevOps (локальная сборка)
> Секрет: ключ `SITE_METRICS_API_KEY` — только в `.env` (chmod 600).
> Значение ключа — в ЧТЗ сайта на Рабочем столе пользователя; в git не попадает.

## 1. Цель

Централизованный мониторинг сайта da-dryclean.ru:
- сбор бизнес-метрик (трафик, лиды, конверсия) — скрейп Prometheus'ом;
- сервисные метрики сервера (node_exporter) и БД (postgres_exporter);
- контроль доступности эндпоинтов метрик (health-коллектор);
- дашборд «Бизнес сайта» + алерты.

Доступ: `https://da-dryclean.ru/metrics/{tracking,content,node,postgres}`
с заголовком `X-Monitoring-Key` (см. ADR-007 D1). Пока сайт не доработан —
эндпоинты отвечают 404/403, `site_metrics_up=0` (ожидаемо).

## 2. Задачи

- **TASK-MON-1** `app/sites.py`: поле `metrics_urls: dict[str, str] | None`
  (ключи `tracking|content|node|postgres`; значения — только https, host
  обязателен, без query/fragment). Тесты валидации.
- **TASK-MON-2** `app/config.py`: `site_metrics_interval_seconds=60`,
  `site_metrics_timeout_seconds=10.0`, `site_metrics_api_key=""` + тесты.
- **TASK-MON-3** `app/metrics.py`: гейджи `monitoring_site_metrics_up`,
  `monitoring_site_metrics_response_code`,
  `monitoring_site_metrics_latency_seconds` (лейблы `site`, `kind`).
- **TASK-MON-4** `app/api/v1/sd.py`: `GET /api/v1/sd/site-metrics/{kind}`
  (404 при неизвестном kind; SD-группы с `site`, `__scheme__`, 
  `__metrics_path__`; target host:443) + тесты.
- **TASK-MON-5** `collectors/sitemetrics.py`: `SiteMetricsCollector`
  (source=`site-metrics`, parallel, без ретраев — ADR-002; HTTP≠2xx и сетевые
  ошибки = данные `up=0`, не ошибка коллектора; заголовок ключа; метрики
  TASK-MON-3; логи `site_metrics_check_done/failed`) + тесты respx
  (200/403/404/таймаут, заголовок, нет metrics_urls → 0 точек).
- **TASK-MON-6** `app/main.py`: регистрация коллектора для сайтов с
  `metrics_urls`; warning при пустом ключе.
- **TASK-MON-7** `prometheus/prometheus.yml` + `prometheus/prometheus-entrypoint.sh`
  + `docker-compose.yml`: 4 job'а `site-*` с http_sd и
  `http_headers: X-Monitoring-Key` (плейсхолдер `__SITE_METRICS_API_KEY__`,
  подстановка entrypoint'ом; env `SITE_METRICS_API_KEY` из .env) + тесты.
- **TASK-MON-8** `prometheus/alerts.yml`: алерты `SiteMetricsEndpointDown`
  (up==0, 5m, warning) и `SiteNoTraffic` (business_page_views_24h==0, 3h,
  warning) + обновить test_alerts.
- **TASK-MON-9** `grafana/dashboards/site-business.json`: uid
  `site-business`, переменная `site`, 14 панелей (см. ADR-007 D7),
  datasource `prometheus`, без rate() на monitoring_* + тесты.
- **TASK-MON-10** `config/sites.yml`: добавить `da-dryclean.ru` с
  `metrics_urls`; `.env.example` + `.env`: `SITE_METRICS_API_KEY`;
  обновить ARCHITECTURE.md.

## 3. Критерии приёмки

1. `pytest && ruff check . && ruff format --check . && mypy .` — зелёные.
2. `GET /api/v1/sd/site-metrics/tracking` отдаёт
   `[{"targets":["da-dryclean.ru:443"],"labels":{"site":"da-dryclean.ru","__scheme__":"https","__metrics_path__":"/metrics/tracking"}}]`.
3. `monitoring_site_metrics_*{site="da-dryclean.ru"}` присутствуют в
   `/metrics` локальной сборки; до доработки сайта `up=0`.
4. Prometheus: 4 job'а site-* сконфигурированы, цели появляются в UI;
   конфиг валиден (entrypoint подстановка, promtool-совместим).
5. Дашборд «Бизнес сайта» загружается в Grafana, переменная site работает.
6. Алерты SiteMetricsEndpointDown/SiteNoTraffic в `/api/v1/rules` Prometheus.
7. Ключ не встречается ни в одном файле репозитория.

## 4. Декомпозиция и маршрутизация

BCK: TASK-MON-1..6, 8 · INF: TASK-MON-7, 10 · FRT: TASK-MON-9.
Исполнитель: Разработчик. Проверка: Тестировщик (глубокая, пофайловая).
Деплой: DevOps — локальная сборка docker compose (прод мониторинга — после
подтверждения пользователя о доработке сайта).
