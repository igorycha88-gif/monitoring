## 1. Контекст

Владелец хочет на вкладке «Бизнес сайта» (site-business.json):

1. Поле «количество кликов по номеру телефона за 12 часов»;
2. График, показывающий во сколько был каждый клик (точное время).

Источник — БД сайта (конвейер ЭПИК-9/ADR-010), НЕ Яндекс.Метрика.
Факт-чек 2026-08-29: сайты клики по телефону сейчас НЕ собирают;
da-dryclean.ru не отдаёт `/metrics/tracking` вовсе. Сайтовая часть —
парное ЧТЗ; это ЧТЗ — только мониторинг-репо.

## 3. Требования

### 3.1 Prometheus (TASK-INF-001)

- В `global` добавить `out_of_order_time_window: 25h` с комментарием-ссылкой
  на ADR-012 (repeat-выдача событийных семплов = дубликаты, дедупликация).

### 3.2 Дашборд (TASK-FRT-001)

Дашборд site-business.json, 14 → **16 панелей**, новая секция y=36:

1. **stat** «Клики по телефону (12ч)»:
   - expr: `max by (site) (business_phone_clicks_12h{site="$site"})`
   - gridPos: x=0, y=36, w=6, h=8; graphMode=area; datasource uid=prometheus
   - пороги: null=blue (нет кликов — не «плохо»)
2. **timeseries** «Клики по телефону (время клика)»:
   - expr: `max by (site) (business_phone_clicks_event{site="$site"})`
   - gridPos: x=6, y=36, w=18, h=8
   - drawStyle=`bars`, fillOpacity=100, lineWidth=0, stacking=off
   - tooltip mode=multi; legend calcs=lastNotNull
   - семпл значения 1 с ts=момент клика → бар «во сколько кликнули»

Обе панели: агрегация `max by (site)` (дедупликация серий,
ЧТЗ_Фикс_Задвоение_Бизнес_Сайта), фильтр `site="$site"`.

### 3.3 Тесты (TASK-TST-001/002)

- `test_site_business_structure`: 16 панелей, +2 тайтла;
- `test_site_business_panels_use_business_and_site_metrics`: +
  `business_phone_clicks_12h`, `business_phone_clicks_event`;
- новый `test_prometheus_out_of_order_window` (или аналог): global
  `out_of_order_time_window == "25h"`.

## 4. Критерии приёмки

1. `pytest && ruff check . && ruff format --check . && mypy .` — зелёные.
2. Дашборд валиден (JSON, datasource uid=prometheus, переменная site).
3. Все новые expr содержат `max by (` и `site="$site"`.
4. Prometheus-кониг содержит `out_of_order_time_window: 25h` и остаётся
   без секретов (тест ADR-010 не сломан).
5. Локальный деплой (полная пересборка) здоров; существующее окружение не затронуто.

## 5. Ограничения и риски

- Панели покажут «Нет данных» до реализации сайтовой части (парные ЧТЗ) —
  ожидаемое состояние, не баг.
- OOO-окно глобально: на прочие метрики (без явных ts) не влияет.
- Секреты не в коде/коммитах; ключ da-dryclean появится только в прод `.env`
  при реализации сайтовой части (DevOps-операция вне этого ЧТЗ).
