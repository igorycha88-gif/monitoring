# ЧТЗ: Фикс рендера недельных метрик Вебмастера (latest_weekly смешивает снапшоты)

**Дата:** 2026-08-23
**Маршрут:** Аналитик → Разработчик → Тестировщик → DevOps (постдеплойный рестарт, Правило 7)
**Симптом пользователя:** «нет данных по кликам за неделю и показы за неделю»

## 1. Диагностика (факты с прода)

1. Серверная цепочка исправна: /metrics отдаёт `monitoring_search_clicks_total/shows_total`,
   Prometheus скрейпит без разрывов 3 дня, Grafana API возвращает данные для панелей
   «Клики за неделю»/«Показы за неделю» во всех диапазонах для обоих сайтов.
2. «No data» в браузере не воспроизводится серверно — вероятная причина на клиенте
   (устаревшая вкладка/выбор переменной). Пользователю рекомендовано обновить вкладку.
3. **Подтверждённый дефект:** `WebmasterStorage.latest_weekly()` (app/storage.py:203)
   выбирает последнюю строку КАЖДОГО `(site, query_id)` независимо:
   - запросы, выпавшие из топ-50 Вебмастера, рендерятся вечно со старыми значениями
     (у weekly нет временно́го фильтра, в отличие от `latest_daily(since_date)`);
   - сумма по сайту завышена: прод рендерил клики 10 / показы 1203 при актуальном
     снапшоте 7 / 1078 (da-dryclean.ru), показы 138 вместо 135 (эвакуация.online);
   - значения в Prometheus не менялись (`changes(...[3d]) == 0` у всех серий).

## 2. Решение

Выбирать не «последнюю строку каждого запроса», а **последний снапшот САЙТА целиком**:
все строки, у которых `fetched_at = MAX(fetched_at)` по сайту. Снапшот `/popular` —
когерентный срез (скользящее окно Вебмастера на момент запроса); смешение снапшотов
разных прогонов некорректно. Поведение при долго неудачном сборе сайта — рендер
последнего успешного снапшота (как и сейчас), приемлемо.

## 3. Задачи

- **TASK-BCK-1:** `app/storage.py` — `latest_weekly()`: выбирать строки
  `WHERE fetched_at = (SELECT MAX(fetched_at) FROM webmaster_weekly w2 WHERE w2.site = w.site)`
  (гранулярность — сайт, не пара сайт+запрос). Обновить docstring.
- **TASK-BCK-2:** Обновить/добавить тесты в `tests/test_storage.py`:
  - happy path: два снапшота сайта → возвращается только последний;
  - запрос, выпавший из топ-50 (есть в старом снапшоте, нет в новом), НЕ возвращается;
  - разные сайты имеют независимые MAX(fetched_at);
  - пустая таблица → `[]`.

## 4. Критерии приёмки

1. `latest_weekly()` возвращает строки только последнего снапшота каждого сайта.
2. Выпавшие из топ-50 запросы не попадают в рендер.
3. `pytest && ruff check . && mypy .` — зелёные; покрытие новых веток ≥ 60%.
4. Существующие дашборды/метрики не меняются (имена/лейблы прежние).
5. DevOps: полная пересборка стека + прод-деплой + smoke-проверка значений.

## 5. Файлы

- `tests/test_storage.py` (тесты)
