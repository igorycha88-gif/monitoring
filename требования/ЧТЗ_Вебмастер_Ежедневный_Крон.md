# ЧТЗ: Расписание Вебмастера — раз в день в 07:00 по Москве

## Задача
Сбор данных Яндекс.Вебмастера выполняется раз в час. Требуется: раз в день, в 07:00 Europe/Moscow (данные Вебмастера обновляются ежедневно — часовой сбор избыточен).

## Изменения (5 файлов)
1. `collectors/base.py` — новый метод `register_daily(scheduler, hour, timezone)`: CronTrigger(hour=hour, timezone), `next_run_time=now` (данные сразу после рестарта), `misfire_grace_time=20ч` (пропущенный из-за сна машины запуск выполняется при пробуждении)
2. `app/config.py` — `webmaster_interval_seconds` → `webmaster_cron_hour: int = 7` + `webmaster_cron_timezone: str = "Europe/Moscow"`
3. `app/main.py` — вебмастер регистрируется через `register_daily`
4. `.env.example` — `WEBMASTER_INTERVAL_SECONDS` → `WEBMASTER_CRON_HOUR=7` (+ комментарий)
5. `tests/test_base_collector.py` — тесты `register_daily`: cron-поля, таймзона, misfire grace, немедленный первый запуск

## Не меняется
- uptime/ssl/metrika/site-metrics — остаются на interval-триггере
- Логика сбора WebmasterCollector, метрики, дашборды

## Критерии приёмки
1. Джоба `collector_webmaster` имеет cron-триггер: hour=7, timezone Europe/Moscow (= 04:00 UTC)
2. Первый запуск — сразу при старте приложения
3. misfire_grace_time = 20ч: запуск, пропущенный из-за сна, выполняется при пробуждении
4. Остальные коллекторы работают по interval, как раньше
5. pytest && ruff && mypy проходят; покрытие ≥ 60%

Аналитик → Разработчик → Тестировщик → DevOps
