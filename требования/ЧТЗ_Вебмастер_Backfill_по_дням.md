# ЧТЗ (упрощённое): Разовый backfill по-дневной истории Вебмастера в SQLite

> Версия: 1.0 · Дата: 2026-08-20
> Маршрут: Аналитик → Разработчик → Тестировщик → DevOps
> Архитектор: НЕ ТРЕБУЕТСЯ (переиспользуются API-клиент и схема БД ADR-009, новых механик нет)

## Задача

По-дневная история Вебмастера (`webmaster_daily`) содержит только дни после
подключения сайтов (коллектор пишет 1 новейший завершённый день за запуск,
ADR-008 D1). Наполнить историю задним числом: API Вебмастера отдаёт per-query
history за окно до 31 дня.

## Решение

Разовый скрипт `scripts/backfill_webmaster_daily.py`:

1. Читает `config/sites.yml` + `Settings` (персайтные токены
   `webmaster_token(domain)`, как в коллекторе).
2. Для каждого сайта с `webmaster_host_id`:
   - берёт топ запросов (`/search-queries/popular`, как коллектор);
   - на каждый запрос запрашивает history за `WEBMASTER_HISTORY_DAYS`
     (окно до 31 дня; дефолт 7 — конфигурируется env на время прогона);
   - все **завершённые** дни (кроме сегодняшнего по Europe/Moscow)
     записывает в `webmaster_daily` через существующий
     `WebmasterStorage.save_daily` (upsert — повторный прогон безопасен).
3. Логирование: начало/конец, сайт, запросов, дней, записей, ошибки
   (структурированный logger, токены не логируются).
4. Работает внутри контейнера (`docker exec`), пишет в volume `monitoring-db`.
5. Ретраи/лимиты: последовательный обход, пауза между запросами 0.5 с
   (лимиты API Вебмастера), 429 — остановка с понятной ошибкой.

## Критерии приёмки

1. `pytest && ruff check . && ruff format --check . && mypy .` — зелёные
   (новых тестов не требуется: скрипт переиспользует протестированные
   `WebmasterCollector._fetch_queries/_fetch_query_history` и storage;
   pylint-чистота и типизация обязательны).
2. После прогона в `webmaster_daily` появились строки за каждый завершённый
   день окна (проверка SQL: `GROUP BY site, date`).
3. Повторный прогон не создаёт дублей (upsert).
4. Регрессия: обычный cron-сбор Вебмастера работает как раньше.
5. Токены в логи/вывод не попадают.
