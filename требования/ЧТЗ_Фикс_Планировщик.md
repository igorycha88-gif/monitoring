# ЧТЗ (упрощённое): Фикс планировщика — немедленный первый запуск коллекторов

## Проблема (постдеплойная)
1. Первый запуск collector-заданий происходит только через полный интервал
   (для webmaster — 1 час данных нет после старта).
2. APScheduler пропускает опоздавшие задания: "was missed by 0:06:49" —
   первый запуск webmaster в 11:42:50 отменён, следующий перенесён на 12:42:50.
   Причина: misfire_grace_time по умолчанию = 1 сек (ноутбук спал / event loop занят).

## Изменения
1 файл: `collectors/base.py`, метод `register()`:
- `next_run_time=now` — первый запуск сразу после старта приложения
- `misfire_grace_time=interval_seconds` — опоздавший запуск выполняется, а не отменяется

## Критерии приёмки
1. После старта приложения каждый коллектор выполняется в первые секунды (webmaster_collect_done в логах сразу)
2. Опоздание задания < интервала не отменяет запуск
3. Существующие тесты не сломаны,新增 тест на register() (next_run_time/misfire_grace_time)
4. pytest && ruff && mypy проходят

## Регрессия (Правило 5)
uptime (60с), ssl (3600с), metrika (300с), site-metrics — все используют тот же register();
изменение безопасно: idempotent-задания, max_instances=1 сохранён.

## Маршрутизация
Аналитик → Разработчик → Тестировщик → DevOps
