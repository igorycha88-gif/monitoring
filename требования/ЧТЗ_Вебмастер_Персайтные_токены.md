# ЧТЗ: Персайтные OAuth-токены Яндекс.Вебмастера

> Версия: 1.0 · Дата: 2026-08-19
> Маршрут: Аналитик → Разработчик → Тестировщик → DevOps
> Архитектор: НЕ ТРЕБУЕТСЯ — переиспользуется паттерн ADR-010 (персайтные
> ключи X-Monitoring-Key): JSON-словарь {домен: секрет} в `.env` + fallback
> на глобальное значение. Новых метрик/лейблов/API-эндпоинтов нет.

## Задача

Сайты мониторинга верифицированы в **разных** аккаунтах Яндекс.Вебмастера
(da-dryclean.ru — uid 2298186322, эвакуация.online — отдельный аккаунт
владельца). API Вебмастера отдаёт данные только по хостам аккаунта токена.
Сейчас коллектор поддерживает один общий `YANDEX_WEBMASTER_OAUTH_TOKEN` —
второй и последующие сайты подключить нельзя.

Сделать модель «токен на сайт» (решение владельца): сколько сайтов — столько
токенов.

## Решение (по образцу ADR-010 D1)

1. **`.env`** — новая переменная `YANDEX_WEBMASTER_OAUTH_TOKENS`:
   JSON `{"<domain>": "<token>"}` (домен — unicode, как в sites.yml).
   Глобальный `YANDEX_WEBMASTER_OAUTH_TOKEN` остаётся fallback'ом для
   доменов без персонального токена (обратная совместимость: da-dryclean.ru
   продолжает работать без правок .env).
2. **`app/config.py`** — `yandex_webmaster_oauth_tokens` (NoDecode +
   валидаторы как у `site_metrics_api_keys`: JSON-объект, домены в нижний
   регистр) + метод `webmaster_token(domain) -> str`
   (персональный → глобальный → "").
3. **`collectors/webmaster.py`**:
   - конструктор: вместо `oauth_token: str` принимает `oauth_tokens:
     dict[str, str]` (домен → токен; "" — глобальный fallback);
   - `collect_site`: токен сайта пуст → `WebmasterConfigError` (ошибка
     сайта, как у Метрики — видимая, не тихая);
   - `user_id` кэшируется **на токен** (`dict[str, int]`): у каждого
     аккаунта свой uid; запросы /popular и /history идут с токеном сайта.
4. **`app/main.py`** — передать карту токенов
   (`settings.webmaster_token(site.domain)` для сайтов с host_id);
   warning при пустых токенах (по образцу site_metrics_api_keys_empty).
5. **`.env.example`** — задокументировать переменную (без значений).
6. **`config/sites.yml`** — добавить `webmaster_host_id` эвакуация.online
   (точное значение — из `GET /v4/user/{uid}/hosts` после получения токена
   владельца; формат `https:<host>:443`).

## Тесты (Правило 8)

- config: парсинг JSON / пустой строки / мусора; нижний регистр доменов;
  resolver персональный → глобальный → "";
- коллектор: заголовок Authorization содержит токен нужного сайта;
  user_id кэшируется на токен (два сайта/два токена → два /user-запроса);
  пустой токен сайта → WebmasterConfigError (collector_site_error);
  логирование webmaster_collect_done/webmaster_collector_init с
  персональными токенами (без значений токенов в логах!);
- регрессия: все существующие тесты webmaster/metrika/config зелёные.

## Критерии приёмки

1. `pytest && ruff check . && ruff format --check . && mypy .` — зелёные.
2. Сайты из разных аккаунтов собираются в одном цикле: каждый со своим
   токеном и uid; da-dryclean.ru (глобальный токен) — без изменений в .env.
3. Пустой токен сайта → пер-сайтовая ошибка (коллектор жив, другие сайты
   собираются), `CollectorFailing` отражает только падающий сайт.
4. Токены не попадают в логи/код/коммиты (`git grep` пуст).
5. После выдачи токена владельцем и полной пересборки:
   `monitoring_search_clicks_total{site="эвакуация.online", ...}` появляются
   после первого cron-цикла Вебмастера.
6. Регрессия: da-dryclean.ru, Метрика, uptime/SSL, site-metrics — как раньше.
