# ЧТЗ: Коллектор Яндекс.Вебмастера (ЭПИК-5)

- Дата: 2026-08-14
- Маршрут: Аналитик → Архитектор ✅ → Аналитик → Разработчик → Тестировщик → DevOps
- Основание: BACKLOG.md ЭПИК-5 (TASK-050/051), ADR-004

## 1. Цель

Сбор поисковых запросов (клики, показы, позиции) из API Яндекс.Вебмастера
по каждому сайту с `webmaster_host_id`, публикация в Prometheus. История
позиций строится TSDB (точка раз в час).

## 2. Требования

### Функциональные

1. Раз в час (`webmaster_interval_seconds=3600`) последовательно обходить
   сайты из `config/sites.yml` с заполненным `webmaster_host_id`.
2. Запрос: `GET https://api.webmaster.yandex.net/v4/user/{uid}/hosts/{host_id}/search-queries/popular`
   с `order_by=TOTAL_CLICKS`, `query_indicator=TOTAL_SHOWS`,
   `query_indicator=TOTAL_CLICKS`, `query_indicator=AVG_SHOW_POSITION`,
   `limit=webmaster_top_queries` (50), заголовок `Authorization: OAuth
   <YANDEX_WEBMASTER_OAUTH_TOKEN>`. Окно данных — последняя неделя (дефолт API).
3. `uid` разрешается лениво: `GET /v4/user` (с ретраями), кэшируется
   в коллекторе; повторяется каждый цикл только при отсутствии кэша.
4. Метрики (Gauge, лейблы строго `{site, query}`):
   - `monitoring_search_clicks_total` — клики за последнюю неделю
   - `monitoring_search_shows_total` — показы за последнюю неделю
   - `monitoring_search_position` — средняя позиция показа
5. Лейбл `query` нормализуется: strip + схлопывание пробелов + обрезка
   100 символов; `webmaster_top_queries` ограничен сверху 100 (кардинальность).
6. Отсутствующий индикатор в ответе (например, AVG_SHOW_POSITION
   «не определён») → соответствующая метрика не пишется (не 0).
7. Пустой список `queries`/`count=0` — успех, 0 точек.
8. Обработка ошибок (ADR-004 §4): 429 → ретраи с Retry-After (макс 3);
   401/403 → без ретраев; 404 (HOST_NOT_*) → без ретраев; 5xx/timeout/
   транспорт → ретраи; кривой JSON → ошибка без ретраев; пустой токен →
   `WebmasterConfigError`; ошибка сайта не рвёт цикл.
9. Сайты без `webmaster_host_id` пропускаются (`collector_*`-метрики для
   них не создаются); коллектор регистрируется только при наличии таких
   сайтов; при пустом токене — наблюдаемо падает в метриках.
10. Базовые метрики/логи — из `BaseCollector`; токен не попадает в логи.

### Технические

- Новый `collectors/webmaster.py`: `WebmasterCollector(BaseCollector)`,
  `source="webmaster"`, `parallel=False`; ошибки `WebmasterApiError`,
  `WebmasterAuthError`, `WebmasterNotFoundError`, `WebmasterConfigError`,
  `WebmasterServerError`; `parse_retry_after` импортируется из metrika.
- `app/metrics.py`: + `SEARCH_CLICKS_TOTAL`, `SEARCH_SHOWS_TOTAL`,
  `SEARCH_POSITION`.
- `app/config.py`: + `webmaster_interval_seconds: int = 3600`,
  `webmaster_timeout_seconds: float = 10.0`, `webmaster_top_queries: int = 50`.
- `app/main.py`: регистрация `WebmasterCollector` (по аналогии с Метрикой),
  collectors в логе `app_started`.
- `.env.example`: + `WEBMASTER_INTERVAL_SECONDS`, `WEBMASTER_TIMEOUT_SECONDS`,
  `WEBMASTER_TOP_QUERIES`.
- `config/sites.yml`: пример `webmaster_host_id` (формат `https:example.com:443`).
- `ARCHITECTURE.md`: конвенции по метрикам поиска.
- Тесты: `tests/test_webmaster_collector.py` (respx), дополнение
  `tests/test_app_lifespan.py`.

## 4. Критерии приёмки

1. `pytest && ruff check . && ruff format --check . && mypy .` — зелёные.
2. Метрики `monitoring_search_clicks_total{site, query}`,
   `monitoring_search_shows_total{site, query}`,
   `monitoring_search_position{site, query}` пишутся; покрытие новых
   файлов ≥ 60%.
3. Тесты покрывают: happy path (параметры запроса, uid-резолв и его кэш),
   пустой ответ, 429+Retry-After, 429 исчерпаны, 403/404/500/timeout,
   кривой JSON, пустой токен, пропуск сайта без host_id, нормализацию
   query (пробелы/обрезка), отсутствие индикатора, повторный сбор
   (обновление значений), логирование, отсутствие токена в логах.
4. `collector_*`-метрики webmaster-коллектора корректны (success/errors).
5. Существующие коллекторы не меняют поведение (все старые тесты зелёные).
6. `docker compose -p monitoring` полная пересборка — все healthy (DevOps).

## 5. Ограничения и риски

- Лимиты API: ≤22 запросов/час — запас огромный (ADR-004 §5).
- Ручной ввод host_id может ошибаться → наблюдаемо 404 HOST_NOT_*.
- Скользящее окно «неделя» — суммарные клики/показы за 7 дней, gauge.
