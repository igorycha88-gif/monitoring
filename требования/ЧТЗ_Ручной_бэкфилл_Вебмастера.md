# ЧТЗ: Ручная загрузка всех данных из Яндекс.Вебмастера

**Дата:** 2026-08-21
**Маршрут:** 3 (Аналитик → DevOps, операционная задача, без изменений кода)
**Тип:** Упрощённое ЧТЗ (раздел 6 AGENTS.md — изменений файлов нет)

## Задача

По запросу пользователя «загрузи все данные из Вебмастера вручную» выполнить
разовый backfill по-дневной истории поисковых запросов из API Яндекс.Вебмастера
в SQLite (вебмастер-часть долговременного хранилища) в запущенном локальном
стеке.

## Решение

Запуск существующего скрипта `scripts/backfill_webmaster_daily.py` внутри
работающего контейнера `monitoring-app` с окном 31 день (максимум API):

```bash
docker exec -e WEBMASTER_HISTORY_DAYS=31 monitoring-app \
    python scripts/backfill_webmaster_daily.py
```

Скрипт переиспользует WebmasterCollector (ретраи, обработка 429/401/403/404/5xx),
пишет через upsert — повторный прогон безопасен.

## Сайты

- `da-dryclean.ru` (host_id `https:da-dryclean.ru:443`)
- `эвакуация.online` (host_id punycode `https:xn--80aae0ai8cwa4cza.online:443`)

Токены — из `.env` контейнера (env_file). Сайты без `webmaster_host_id`
пропускаются.

## Критерии приёмки

1. Скрипт отработал без Traceback; в логах `backfill_started` → `backfill_site_done` (на каждый сайт) → `backfill_finished` с `rows_written > 0`.
2. Ошибки 429/5xx(API) отретраились; 401/403/404 фиксируются как ошибки сайта, не валят прогон соседних сайтов.
3. Данные видны в SQLite (`webmaster_daily`) volume `monitoring-db`.
4. Существующее состояние стека не изменено (никаких пересборок/перезапусков).
5. Секреты не попали в логи/вывод.
