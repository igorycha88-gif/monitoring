# Верхнеуровневый бэклог проекта «Мониторинг сайтов»

> Живой документ. Порядок эпиков = порядок реализации.
> Каждая задача проходит полный конвейер: Аналитик → [Архитектор] → Разработчик → Тестировщик → DevOps.
> Статусы: `☐ Не начато` | `🔄 В работе` | `✅ Готово`

**Исходные решения (зафиксированы):**
- MVP = каркас + uptime-коллектор + коллектор Яндекс.Метрики
- OAuth-токены Яндекса есть — коллекторы сразу на реальные API (моки только в тестах)
- Парк сайтов: 4–10 → дашборд с переменной `site` обязателен с первой версии
- Алерты — отдельный эпик после MVP

## Правила работы с бэклогом

1. Один эпик = одна сессия конвейера (или несколько, если эпик крупный).
2. Перед эпиком Аналитик создаёт ЧТЗ; для ЭПИК-0/1/2/5 — обязательно с Архитектором (новые источники данных).
3. Статусы обновляются в этом файле после каждого этапа DevOps.
4. Новые задачи добавляем в конец соответствующего эпика либо в «Бэклог идей» ниже.

### Бэклог идей (не в планах фаз)

- Экспорт отчётов (PDF/ссылки)
- Мульти-окружения (staging)
- Сравнение периодов в дашбордах
- Uptime-история SLA (monthly)
