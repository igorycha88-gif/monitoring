# ЧТЗ: Вебмастер — БД как единственный источник метрик (ADR-011)

**Дата:** 2026-08-21
**Маршрут:** 2 (Аналитик → Архитектор → Аналитик → Разработчик → Тестировщик → DevOps)
**ADR:** `требования/ADR-011_Вебмастер_БД_источник_метрик.md`

## Задача

Устранить задвоение пути данных Вебмастера: коллектор пишет ТОЛЬКО в SQLite;
`/metrics` рендерит поисковые метрики ИЗ БД; 31-дневная история импортируется
в Prometheus разовым promtool-импортом. Старый путь (прямые записи gauge из
коллектора) удалить полностью.

## Декомпозиция

| ID | Задача | Файлы |
|----|--------|-------|
| TASK-BCK-001 | Методы чтения БД: `latest_weekly()`, `latest_daily(since)`, `daily_history(end)` | app/storage.py |
| TASK-BCK-002 | `WebmasterExporter`: рендер 5 метрик из БД (GaugeMetricFamily), фоновый поток обновления кэша, ошибки → STORAGE_ERRORS_TOTAL | app/webmaster_export.py (новый) |
| TASK-BCK-003 | Удалить прямые записи gauge из коллектора; points = строки БД | collectors/webmaster.py, app/metrics.py |
| TASK-BCK-004 | Настройки WEBMASTER_RENDER_DAYS (35), WEBMASTER_RENDER_REFRESH_SECONDS (60) | app/config.py |
| TASK-BCK-005 | Wiring: регистрация/остановка экспортёра в lifespan | app/main.py |
| TASK-BCK-006 | Скрипт экспорта истории в OpenMetrics (timestamp'ы, дедуп-сумма) | scripts/export_webmaster_history.py (новый) |
| TASK-INF-001 | `COPY scripts ./scripts` в Dockerfile | Dockerfile |

Дашборды/алерты НЕ меняются (имена метрик сохранены — D5).

## Требования

1. Имена/лейблы метрик рендера идентичны текущим: `monitoring_search_clicks_total`,
   `monitoring_search_shows_total`, `monitoring_search_position`,
   `monitoring_search_daily_clicks`, `monitoring_search_daily_shows` `{site,query}`.
2. None-индикатор не рендерится (не 0). Пустая БД → метрики отсутствуют.
3. Рендер без timestamp'ов; чтение БД — фоновый поток (не в scrape, не в event loop).
4. Ошибка чтения БД: лог + `STORAGE_ERRORS_TOTAL{source="webmaster-export"}`,
   отдаётся последний кэш.
5. Коллектор: `monitoring_collector_*` сохраняются; weekly/daily пишутся в БД
   как раньше; gauge-записи удалены.
6. Экспорт истории: только daily-метрики; timestamp = дата 00:00 UTC (мс);
   дедупликация суммой по (site, query, date); `--end` включительно; сортировка
   по сериям; `# EOF`.
7. Логирование во всех новых файлах (structlog), метрики — через
   STORAGE_ERRORS_TOTAL (экспортёр) и collector_* (коллектор, уже есть).

## Критерии приёмки

1. `pytest && ruff check . && ruff format --check . && mypy .` — зелёные.
2. Автотесты: чтение БД (последний снапшот/окно/None), рендер (значения, лейблы,
   отсутствие при пустой БД, ошибка чтения), коллектор (БД-записи без gauge),
   конфиг, экспорт-скрипт (формат, дедуп, cutoff), Dockerfile COPY.
3. Прогон в контейнере: `/metrics` содержит поисковые метрики из БД сразу
   после старта app (без ожидания cron).
4. История 21.07–18.08 видна в Prometheus/Grafana после импорта; дублей
   семплов нет (дни до первого семпла TSDB).
5. Существующее приложение и чужие контейнеры не затронуты (Правило 0.1).
