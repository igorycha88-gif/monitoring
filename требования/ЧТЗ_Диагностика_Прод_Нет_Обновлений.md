# ЧТЗ: Диагностика — метрики на проде не обновляются со вчерашнего дня

Дата: 2026-08-24
Маршрут: 3 (Инфраструктурная диагностика) → Аналитик → DevOps
Статус: ✅ выполнено (2026-08-24)

## Проблема

Пользователь сообщает: данные на проде «со вчерашнего дня ничего не поменялось»
по обоим реальным сайтам (da-dryclean.ru, эвакуация.online), по двум источникам:

1. **Серверные метрики сайтов** (site-metrics: tracking/content/node/postgres,
   скрейп через relay app → Prometheus jobs site-*)
2. **Яндекс.Вебмастер** (search_*: сбор 07:00/19:00 МСК → SQLite → рендер)

## Ожидаемое поведение (по конфигу)

- site-metrics health-коллектор: цикл 60 с (SITE_METRICS_INTERVAL_SECONDS)
- relay-скрейпы Prometheus: 15 с, jobs site-*
- Вебмаастер: cron 07:00/19:00 МСК, пишет новейший завершённый день в SQLite
- Рендер search_* из SQLite: фоновый поток 60 с

## Диагностический план (DevOps)

1. Доступ SSH → состояние контейнеров monitoring-* (docker ps, healthcheck)
2. `python3 scripts/verify_prod.py` — полная верификация (§7.1 PRODUCTION.md)
3. Логи monitoring-app: webmaster_collect_done / webmaster_history_done /
   site_metrics_check_* за сегодня; ошибки (429/401/403, transport)
4. SQLite: SELECT site, MIN(date), MAX(date), COUNT(*) FROM webmaster_daily
5. Prometheus: свежесть scrape, up по jobs site-*, значения search_*
6. Изоляция: соседнее приложение smarttraffic-* не затронуто (контроль)

## Критерии приёмки

- Определена причина отсутствия обновлений по обоим источникам
- Устранена (если в нашей зоне ответственности) с соблюдением изоляции
- verify_prod.py: `ИТОГО: N OK, 0 FAIL`
- Существующее приложение НЕ затронуто

## Результаты диагностики (2026-08-24)

1. Серверные метрики (site-metrics, business_*): работают, значения обновляются
   (подтверждено логами + range-запросами Prometheus).
2. Вебмастер, weekly /popular: работает, значения меняются ежедневно.
3. **Баг**: webmaster_daily за 2026-08-21..23 = нули по обоим сайтам.
   Причина: Яндекс финализирует per-query history с лагом >1 суток; штатный
   коллектор пишет только НОВЕЙШИЙ завершённый день — «досчитанные» задним
   числом дни никогда не перезаписываются. Storage (UPSERT + COALESCE) для
   ретро-корректировок уже готов, но данные в него не поступают.
4. Немедленное восстановление: backfill 31 день выполнен (3000 строк) —
   21–22 августа исправлены (193/18 и 154/6 показов).

## Постоянный фикс (TASK-BCK-001)

`WebmasterCollector._write_daily_history`: писать ВСЕ завершённые дни
окна /history (не только новейшую точку). Доп. API-вызовы не требуются —
ответ уже содержит весь window. Backfill-скрипт переиспользует логику
коллектора (уходит дублирование).

### Критерии приёмки

- Каждый прогон (07:00/19:00 МСК) перезаписывает весь 7-дневный window —
  ретро-корректировки Яндекса подхватываются автоматически
- 404 на конкретный query — по-прежнему пропуск, не ошибка сайта
- Автотесты: все завершённые дни окна пишутся; сегодняшний день исключён;
  ретро-коррекция перезаписывает старое значение; COALESCE не затирает NULL
- `pytest && ruff check . && mypy .` — зелёные
