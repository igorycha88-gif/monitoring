# ADR-004: Коллектор Яндекс.Вебмастера (ЭПИК-5)

- Статус: принято
- Дата: 2026-08-14
- Связанные: ADR-001 (модель метрик), ADR-002 (паттерн коллекторов), ADR-003 (API-коллектор Яндекса), BACKLOG.md ЭПИК-5

## Контекст

Нужен сбор поисковых запросов из API Яндекс.Вебмастера (TASK-050/051): клики,
показы, позиции по каждому сайту. OAuth-токен уже зарезервирован в
`Settings.yandex_webmaster_oauth_token`, `webmaster_host_id` — в `SiteConfig`.
Источники: официальная документация API (проверено 2026-08-14):

- `GET /v4/user` → `{"user_id": <int64>}` — uid нужен в пути всех ресурсов;
- `GET /v4/user/{uid}/hosts/{host_id}/search-queries/popular` — ТОП-3000
  запросов за последнюю неделю; `order_by` (TOTAL_SHOWS|TOTAL_CLICKS)
  обязательный, `query_indicator` повторяемый (TOTAL_SHOWS, TOTAL_CLICKS,
  AVG_SHOW_POSITION, AVG_CLICK_POSITION), `limit` 1–500.

## Решения

### 1. Запрос к API

- Данные: популярные запросы за **последнюю неделю** (дефолт API — без
  date_from/date_to: скользящее окно, не требует дат в конфиге).
- `order_by=TOTAL_CLICKS` — топ по кликам (самые ценности-несущие запросы).
- `query_indicator=TOTAL_SHOWS, TOTAL_CLICKS, AVG_SHOW_POSITION`.
  Позиция = **AVG_SHOW_POSITION** (средняя позиция показа) — стандартная
  SEO-метрика, определена даже без кликов (AVG_CLICK_POSITION определён не
  всегда).
- `limit=webmaster_top_queries` (дефолт 50), `device_type_indicator=ALL` (дефолт).
- **user_id разрешается лениво**: первый запрос цикла делает `GET /v4/user`
  (с ретраями), результат кэшируется в экземпляре коллектора. Не делаем это
  в `__init__` (он синхронный) и не требуем от пользователя числовой uid.
- Заголовок `Authorization: OAuth <token>`, timeout `webmaster_timeout_seconds`.
- httpx-клиент создаётся на запрос (как в ADR-003); обход сайтов
  последовательный (`parallel=False` — дефолт базы, лимиты API).

### 2. Модель метрик Prometheus (DoD TASK-050)

Gauge-метрики (имена зафиксированы в DoD бэклога):

- `monitoring_search_clicks_total{site, query}` — клики за последнюю неделю;
- `monitoring_search_shows_total{site, query}` — показы за последнюю неделю;
- `monitoring_search_position{site, query}` — средняя позиция показа.

Особенности:

- Лейблы строго `{site, query}` по DoD (без `source` — осознанно: источник
  один, имя зафиксировано в DoD).
- Суффикс `_total` у gauge — то же осознанное исключение, что в ADR-003:
  клики/показы считаются за скользящее окно, применять напрямую, без rate().
- Точка = одно записанное значение: запрос с полным набором индикаторов =
  3 точки; AVG_SHOW_POSITION может отсутствовать в ответе («значение не
  определено») → метрика позиции для такого запроса не пишется (не 0).
- История позиций (TASK-051) строит Prometheus TSDB: точка раз в час,
  лейбл с датой НЕ вводим.

### 3. Кардинальность (критично для DoD)

- Топ-N запросов: `webmaster_top_queries: int = 50`, при конфигурации
  ограничивается сверху 100 (правило ARCHITECTURE.md: query-лейбл ≤ 100
  рядов на сайт).
- Нормализация текста запроса для лейбла `query`: strip + схлопывание
  пробелов + обрезка до 100 символов. Иначе пользовательский текст
  раздувает кардинальность TSDB.
- Худший случай: 10 сайтов × 100 запросов × 3 метрики = 3 000 рядов —
  приемлемо.
- Запросы, выпавшие из топа, перестают обновляться → Prometheus помечает
  series устаревшими (staleness, 5 мин) — мусор не копится бесконечно.

### 4. Обработка ошибок (как ADR-003, единый паттерн)

| HTTP | Исключение | Поведение |
|------|-----------|-----------|
| 429 | `RateLimitError(retry_after)` | ретраи (3) с Retry-After → ошибка сайта |
| 401/403 | `WebmasterAuthError` | без ретраев (токен/права) |
| 404 | `WebmasterNotFoundError` | без ретраев (HOST_NOT_VERIFIED / NOT_INDEXED / NOT_LOADED) |
| 5xx | `WebmasterServerError` | ретраи |
| timeout/транспорт | `httpx.*` | ретраи (база) |
| кривой JSON | `WebmasterApiError` | без ретраев |
| пустой токен при наличии host_id | `WebmasterConfigError` | без ретраев, наблюдаемо |

- `parse_retry_after` переиспользуется из `collectors/metrika.py` (вынесен
  туда в ADR-003; дублирование не вводим — импортируем).
- Пустой список `queries` и `count=0` — это **данные** (успех, 0 точек).
- Ошибка одного сайта не рвёт цикл (базовый `_collect_site_safe`).

### 5. Rate-limit assessment

- Нагрузка: 1 запрос `/v4/user` на цикл (кэш) + N (≤10) запросов popular
  в час = ≤ 11–22 запросов/час — значительно ниже квот API Вебмастера.
- Webmaster-данные обновляются максимум несколько раз в сутки → интервала
  3600 с более чем достаточно.

### 6. Сайты без host_id и пустой токен

- Сайты без `webmaster_host_id` фильтруются в `__init__` (лог
  `webmaster_collector_init` со `skipped_sites`) — паттерн ADR-003.
- Коллектор регистрируется только если есть хоть один сайт с host_id;
  при пустом токене — регистрируется и наблюдаемо падает в
  `collector_*`-метриках (не «тихо отключён»).

## Альтернативы (отклонены)

- **Просить числовой user_id в sites.yml/.env** — лишний конфиг, uid легко
  получается сам; отклонено.
- **AVG_CLICK_POSITION как «позиция»** — определён только при кликах;
  AVG_SHOW_POSITION полнее.
- **order_by=TOTAL_SHOWS** — показометрика без кликов менее приоритетна.
- **Произвольный date_from/date_to в конфиге** — усложнение MVP; дефолт
  «последняя неделя» стабилен и самодокументируем.
- **source-лейбл в метриках поиска** — отклонено: DoD фиксирует {site, query}.
- **Пагинация (offset) ради >500 запросов** — противоречит лимиту
  кардинальности (топ-N ≤ 100).

## Риски

- Формат host_id (`https:example.com:443`) неудобно вводить вручную —
  ошибочный host_id даст 404 HOST_NOT_* → наблюдаемо в метриках/логах;
  будущий эпик может добавить авторазрешение через /hosts.
- Изменения API Яндекса — моки в тестах изолируют; прод-сбой виден в
  `collector_success`/`errors_total`.
- Тексты запросов — пользовательский ввод: нормализация лейбла ограничивает
  кардинальность; unicode-текст в лейблах Prometheus валиден.
