## Контекст (итог диагностики «не вижу сбора метрик на проде»)

Проверены все источники на проде (130.49.129.241). Сбор работает полностью:

| Источник | Частота | Статус | Доказательство |
|---|---|---|---|
| uptime/ssl | 60с / 1ч | ✅ | success=1 по 4 сайтам, метрики в Prometheus |
| Метрика | 5 мин | ✅ | токен валиден (чужой счётчик → 404, наш → 200), нули реальны |
| Вебмастер | 07:00/19:00 МСК | ✅ | webmaster_daily/weekly пишутся, рендер 540 серий |
| site-metrics (business_*) | 15с | ✅ | 4853 серии, business_sessions_24h{эвакуация}=4 |

Найденные причины «не вижу данных»:

1. **Метрика эвакуация.online = 0 визитов: тег счётчика 111456265 НЕ установлен
   на сайте** (в HTML главной и /evakuatory нет mc.yandex.ru / watch/111456265),
   при этом собственная аналитика сайта видит 4 сессии/3 посетителей за 24ч.
   Требуется доработка на стороне сайта (команда сайта), не мониторинга.
2. **История Вебмастера на проде — только 2 дня** (2026-08-20..21): volume
   `monitoring_monitoring-db` создан при деплое 2026-08-21 13:41, бэкфилл на
   проде не выполнялся (ЧТЗ_Ручной_бэкфилл_Вебмастера выполнялся только
   локально). Дашборды динамики (окна 7д) выглядят пустыми → «сбора нет».
3. Вебмастер-нули по кликам эвакуация.online — реальные (новый сайт: 457
   показов за неделю, 0 кликов). У da-dryclean weekly: 25 кликов / 2715 показов.

## Задача

Выполнить разовый backfill по-дневной истории Вебмастера в SQLite на проде —
окно 31 день (максимум API), существующим скриптом `scripts/backfill_webmaster_daily.py`
в работающем контейнере (без пересборок/перезапусков):

```bash
docker exec -e WEBMASTER_HISTORY_DAYS=31 monitoring-app \
    python scripts/backfill_webmaster_daily.py
```

Скрипт переиспользует WebmasterCollector (ретраи 429/5xx, стоп на 401/403/404),
пишет через upsert — повторный прогон безопасен (ЧТЗ_Ручной_бэкфилл_Вебмастера).

## Критерии приёмки

1. Скрипт отработал без Traceback: в логах `backfill_started` →
   `backfill_site_done` (обa сайта) → `backfill_finished` с `rows_written > 0`.
2. В SQLite `webmaster_daily` появились даты за ~31 день (MIN(date) ≤ 2026-07-25)
   по обоим сайтам.
3. Через ≥60с (refresh рендера) в `/metrics` и Prometheus появились
   ненулевые `monitoring_search_daily_*` для da-dryclean.ru за исторические дни.
4. Существующее приложение (smarttraffic-*) не затронуто; контейнеры мониторинга
   не перезапускались.
5. Секреты в логи/вывод не попали.
