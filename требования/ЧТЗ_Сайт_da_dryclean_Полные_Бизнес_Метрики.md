**Версия:** 1.0
**Дата:** 2026-08-29
**Связанные:** ADR-012 (клики по телефону), ADR-007/ADR-010 (конвейер site-metrics)
**Заказчик:** владелец. Исполнитель — команд(ы) сайтовой части.
**Сайт-образец** (наиболее полный трекинг из трёх): referral/geo/service_clicks

## 2. Требования

### 2.1 Клики по телефону (ADR-012, приоритет 1)

1. Делегированный JS-обработчик `click` на `a[href^="tel:"]`
   (номера: +74952261573, +79852261573 и новые при добавлении) →
   существующий канал событий (`tracking_events`, event_type-словарь уже
   содержит `service_click` — добавить `click_phone`), точный `created_at` в БД.
2. Debounce: не чаще 1 события на ссылку в 5 секунд.
3. Экспорт в `/metrics/tracking`:

```
# HELP business_phone_clicks_12h Phone number (tel:) clicks in the last 12 hours
# TYPE business_phone_clicks_12h gauge
business_phone_clicks_12h 3

# HELP business_phone_clicks_event Phone click events (last 24h), one sample per click with exact click timestamp
# TYPE business_phone_clicks_event gauge
business_phone_clicks_event 1 1753940520000
business_phone_clicks_event 1 1753969080000
```

Правила: `12h` — gauge-окно, пересчёт в 60с-цикле (рядом с существующими
business_*-окнами); `event` — один семпл `1` на клик за 24ч, третий токен —
unix-мс момента клика, по возрастанию, без лейблов, значение строго `1`
(дедупликация, ADR-012 D2/D3); кликов нет — метрики не рендерятся; кэш
рендера до 60 минут допустим.

### 2.2 Эндпоинт `/metrics/postgres` (приоритет 2)

- Реализовать по образцу эвакуация.online / zabor-i-naves.ru (метрики
  рантайма и/или pg_*: соединения, транзакции, размер БД) за тем же
  заголовком X-Monitoring-Key.
- Альтернатива по решению владельца: исключить kind `postgres` — тогда
  мониторинг уберёт его из `metrics_urls` в sites.yml (правка репо
  мониторинга); по умолчанию — реализовать.

### 2.3 Персайтный ключ (ADR-010, приоритет 2)

- Сгенерировать уникальный ключ da-dryclean.ru, передать владельцу
  мониторинга → `SITE_METRICS_API_KEYS` прода `.env` (в git не попадает);
  после этого fallback-ключ перестаёт обслуживать этот сайт.

### 2.4 Подключение Яндекс.Метрики (приоритет 2, владелец)

- Сообщить `counter_id` установленного на сайте счётчика (mc.yandex
  в HTML есть) и выдать OAuth-токен с правом «Чтение статистики» на него
  (или токен, покрывающий все счётчики владельца).
- Мониторинг добавит `metrika_counter_id` в sites.yml; токен → `.env` прода.

### 2.5 node_exporter (приоритет 4, серверная часть)

- Установить node_exporter на сервере сайта; сообщить URL вида
  `http://<host>:9100` — мониторинг добавит `node_exporter_url`
  в sites.yml (правка репо мониторинга, не сайта).

## 3. Критерии приёмки

1. Клик по любому из номеров создаёт `click_phone` с корректным
   `created_at` (БД).
2. `curl -H "X-Monitoring-Key: <ключ>" https://da-dryclean.ru/metrics/tracking`
   отдаёт обе метрики телефона; timestamp'ы точны до секунды;
   `business_phone_clicks_12h` сходится с БД.
3. `/metrics/postgres` отвечает 2xx (или kind исключён решением владельца) —
   панель «Эндпоинты метрик» = UP, алерт SiteMetricsEndpointDown гаснет.
4. После п.2.3–2.4: доступ только по персайтному ключу; панели
   «Визиты/Посетители» с данными (`monitoring_collector_success{source="metrika",
   site="da-dryclean.ru"}=1`).
5. Повторные запросы эндпоинтов не создают дублей событий; ответ < 1 с.
6. После п.2.5 и правки sites.yml — серверные панели «Обзора сайта» с данными.

## 4. Вопросы

Нет: форматы метрик зафиксированы ADR-012; собственный трекинг сайта —
образец для остальных.
